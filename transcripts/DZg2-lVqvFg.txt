So I'm sure you've heard the term agent being thrown a lot recently, but what exactly is an agent? You have your chatbots like ChatGPT, which are question and answer based, meaning you give it a simple question and it returns a simple answer. Well an agent is just one step further, it's a chatbot that can take actions for you. These actions include writing code for you, checking your email, checking your calendar, booking you appointments, whatever you may want. Now the most important thing about the agent isn't the underlying model that powers it, but it's something called the harness. And what the harness is, is it's the orchestration layer that sits around and actually calls the model through APIs or SDKs. The harness consists of five very key pieces, namely the system prompt, the memory, the tools, the context architecture, and the sub-agent architecture. Memory and context management are just two ways for the agent to store what's already been said in the conversation. A great way to do this is through a PostgreSQL database that stores turn-based conversation data. A system prompt is self-explanatory. It's just instructions on what the agent is meant to do. Tools are the actual mechanism by which the agent can take an action. These can wrap API endpoints to order you food. These can write your code. These can, again, do any of the actions that I mentioned before. Sub-agents are just a way for the broader agent to chunk a task into different little bite-sized pieces that can then be tackled on their own. More specifically, a sub-agent is its own thread that can have its own system prompt, own context, own memory, and it's kicked off by the parent agent through a tool call.
